# Разделение логики чата

Сейчас есть один большой use_case - [chat](src/use_cases/chat/chat.rs)

Чат в данном случае - это интерактивный цикл общения с агентом и в этом случае цикл поддердживает такие варианты взаимодействия:

- пользователь отправляет промпт в модель
- Модель отвечает пользователю
- Модель вызывает tools
- Цикл автоматически отправляет в модель результат выполнения tools

Кроме этого есть еще и recovery

Важный момент: этот цикл интерактивный.

Самому use_case Chat нужны вспомогательные структуры данных, каждая из которых выполняет свои задачи, эти структуры также находятся в каталоге [chat](src/use_cases/chat)

Что нужно сделать:

1. Вынести shared-логику этого use_case в shared:

- файл src/use_cases/chat/command_parser.rs нужно перенести в src/shared/command_parser.rs
- файл src/use_cases/chat/history_sync.rs нужно перенести в src/shared/history_sync.rs
- файл src/use_cases/chat/invalid_response.rs нужно перенести в src/shared/invalid_response.rs, как и сам список invalid responses: src/use_cases/chat/invalid_response.txt
- файл src/use_cases/chat/recovery_error.rs нужно перенести в src/shared/recovery_error.rs
- файл src/use_cases/chat/stream_output_state.rs нужно перенести в src/shared/stream_output_state.rs
- файл src/use_cases/chat/streamed_turn.rs нужно перенести в src/shared/streamed_turn.rs
- файл src/use_cases/chat/tool_recovery.rs нужно перенести в src/shared/tool_recovery.rs
- файл src/use_cases/chat/turn_journal.rs нужно перенести в src/shared/turn_journal.rs
- файл src/use_cases/chat/turn_recovery.rs нужно перенести в src/shared/turn_recovery.rs

2. Обновить импорты чтобы ничего не поломалось

После этого нужно на основе имеющегося файла src/use_cases/chat/chat.rs составить план того как будет выглядеть НЕИНТЕРАКТИВНЫЙ Subagent. Он должен находиться в src/use_cases/subagent/subagent.rs

Отличия Subagent от Chat будет только в том что в нем нельзя будет запрашивать пользователя вообще:

- Он запускается с промптом, который изначально был передан (это будет текст с промптом-инструкцией)
- Он может вызывать tools такие же как и chat
- Он НЕ может запрашивать у пользователя ввод, действует автономно.
- В конце он должен выдать отчет о своей работе настолько подробно насколько это возможно. Формат отчета о работе должен быть жестко задан. Для того чтобы модель понимала какой формат отчета необходим я предлагаю создать базовый промпт который нужен для формирования этого отчета в src/prompts/subagent.md

Пока что никуда его не подключаем, надо просто покрыть тестами в соответствии с гайдлайнами по тестированию в AGENTS.md и проверить тестами что код рабочий.

Важно: не меняй файлы которые не относятся к задаче.
